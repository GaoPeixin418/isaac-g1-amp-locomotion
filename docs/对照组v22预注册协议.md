# 对照组（WARMUP=0，纯 v2.2）预注册协议

> 建立于 2026-11-11 16:0x，**在训练启动之前**。
> 目的：把"什么算学会、什么算失败、失败后怎么走"在数据出现前写死，
> 防止事后挑指标——这是本项目已经踩过三次的坑（见 MEMORY 3.5 / 3.7 / 3.8）。

## 一、为什么要先跑这一组

v2.2 的历史 run（`2026-10-27_23-56-50`）**只跑到 iter 84/2400，5 分 15 秒，00:03 断电**。
取证结论（详见 `v2.2结案与v2.3方案.md`）：

| 证据 | 事实 |
|---|---|
| run 目录 | 只有 `model_0.pt`，无 model_200/400 |
| `v22_curve.csv` | 101 字节，**只有表头，零行数据** |
| `train_fresh_v22.log` | 停在 `Learning iteration 84/2400` |

**所以"v2.2 配置能不能学会走路"至今没有实测证据。** 现有的只有：
- v2（work_asym **−2.0**）在 iter 800 被判死（v_act 0.06）
- v2.1（回退 angvel，work_asym 仍 −2.0）在 iter 1200 仍 0.07

而 v1 的相变发生在 **iter 400→800 之间**（v_act 0.06 → 0.97）。
换句话说：**v2 被处死的那一刻，v1 才刚学会走路。** 这个巧合让"权重 −2.0 是主因"从结论降级为嫌疑。

对照组就是把 work_asym 改回 −1.0、其余与 v2.2 完全一致，给它一次真正的机会。

## 二、两组设计（同一份源码，只差一个环境变量）

| 项 | 对照组（本组） | 实验组 v2.3 |
|---|---|---|
| 启动命令 | `bash 38_run_ctrl_v22.sh` | `bash 37_train_fresh_v23.sh` |
| WARMUP | **0**（无斜坡） | 12000 步（500 iter） |
| `leg_work_asymmetry` weight | −1.0 | −1.0 |
| time_constant | 1.5 s | 1.5 s |
| `ang_vel_xy_l2` | −0.05 | −0.05 |
| `feet_air_time` threshold | 0.4 | 0.4 |
| λ (`task_style_lerp`) | 0.5 | 0.5 |
| MAX_ITER | **1600** | 3000 |
| seed | 42 | 42 |
| 训练日志 | `/data/logs/train_ctrl_v22.log` | `/data/logs/train_fresh_v23.log` |
| 曲线 | `/data/progress/ctrl_v22_curve.csv` | `/data/progress/v23_curve.csv` |
| run 目录 | 新建（启动后自动捕获） | 新建 |

除 WARMUP 与 MAX_ITER 外**全部一致**，所以两组结果的差异可以归因到 warmup。

### 为什么对照组只跑 1600 而不是 3000

v1 的相变在 400→800，1600 给 4 个评估点（400/800/1200/1600）已经覆盖相变窗口 + 2 倍余量。
对照组的问题只有一个是非题——**"能不能学会走路"**，不是"能训到多好"。
真要拿它做最终指标对比，再续训到 3000 即可（`--resume`）。

## 三、预注册判定阈值（不允许事后更换）

监控每 400 iter 出一次评估（`save_interval=200` 的倍数），测 1.0 m/s 档。

| 检查点 | 阈值 | 判定 |
|---|---|---|
| iter 400 | v_act ≥ 0.20 | **有戏**（v1 同点仅 0.06，此时还不用紧张） |
| iter 800 | v_act ≥ 0.70 | **起飞**（v1 同点 0.97） |
| iter 1200 | v_act < 0.20 | **判死**，never-walk 早停自动杀掉 |
| iter 1600 | 走满仍 < 0.20 | **证伪**"v2.2 配置可训" |

> 为什么用 `v_act`（实际水平速率）当硬门槛：它是唯一无法被"作弊式优化"绕开的量。
> 对称性、步频、膝角都可以在"站着不动"或"原地抖腿"的状态下变好看（MEMORY 3.9），
> 只有速度必须真的走过去。

## 四、三种结局 → 下一步动作（也提前定好）

### 结局 A：对照组学会走路（iter 800 v_act ≥ 0.7）

说明 **warmup 不是必需的瓶颈**，v2.2 配置本身可训。此时：
1. 等 1600 跑满，取 legAI / 步频 / 步长 / 膝角四项全指标（`full_eval.py` 六档）
2. 若 **legAI ≤ 15%** → 跛行已根治，项目收尾，**v2.3 不必跑**，省 3 小时
3. 若 **legAI > 15%** → 配置能训但约束偏弱，下一步加权重**但只 +50%（−1.0 → −1.5）**，
   绝不翻倍（MEMORY 3.9：翻倍会让策略学会站着不动）

### 结局 B：对照组判死（iter 1200 仍 < 0.2）

**证伪"v2.2 配置可训"**，warmup 假设获得支持。立刻上 v2.3：
```bash
bash /data/setup/37_train_fresh_v23.sh     # WARMUP=12000，MAX_ITER=3000
```
这是一条干净的因果链：同一套权重，只加"前 500 iter 不加约束"就学会 → 说明
约束确实是在 motor primitive 形成期把探索压死了（对上 MEMORY 3.6）。

### 结局 C：模糊（v_act 落在 0.2–0.7 之间）

不急着判。看曲线趋势：
- 还在涨 → 续训到 2400（`--resume`）
- 平台不动 → 按结局 B 处理，但**证据强度降一档**（"可能"而不是"证实"）

## 六、与历史各组的可比性声明（诚实边界）

| 对比 | 可不可比 | 原因 |
|---|---|---|
| 对照组 vs v1（legAI 42.6%） | **二值可比，指标不可比** | v1 训了 3000 iter，对照组 1600；训练量不同不能直接比数值 |

不能说"和 v1 一样好"——训练量差近一半。

## 七、操作手册

### 现在（无卡模式）能做的
```bash
bash /data/setup/38_run_ctrl_v22.sh --check
# 五道前置校验，前四道应全 OK，第五道报"GPU 不可见"= 正常
```

### 切到有卡模式后
```bash
bash /data/setup/38_run_ctrl_v22.sh
# 约 5 秒返回，自动完成：五道闸 → 启训练 → 等 run 目录 → 锁目录启监控
```

### 看进度
```bash
tail -f /data/logs/train_ctrl_v22.log | grep "Learning iteration"
column -s, -t /data/progress/ctrl_v22_curve.csv
tail -20 /data/logs/watch_ctrl_v22.log
```

### 停止
```bash
pkill -f 'rsl_rl/[t]rain.py'; pkill -f 'watch_[v]2.py'
```
> 注意正则写法 `[t]rain` / `[v]2`：10-27 踩过 `pkill -f pkill` 把自己那条 shell 一起杀导致的 SSH 断连。

### 收工必做（无论成败）
```bash
python scripts/sync_from_server.py --dirs /data/logs /data/progress /data/eval_out \
  /data/legged_lab/logs/rsl_rl/g1_amp/<新run目录>/params
```
