## 1. 技术栈总览

| 层 | 选择 | 版本 | 为什么 |
|---|---|---|---|
| 仿真器 | Isaac Sim | **5.1.0**（pip `isaacsim[all,extscache]`，约 20GB） | AMP/BeyondMimic 类项目要求 Isaac Lab ≥ 2.2 |
| 仿真框架 | Isaac Lab | **v2.3.2**（git clone tag） | 2.3.2 ↔ Sim 5.1 是官方对位组合 |
| RL 框架 | rsl_rl | `zitongbai/rsl_rl` 的 **feature/amp fork**（`pip install -e`） | AMP 的判别器与奖励混合在这个 fork 里，会覆盖 PyPI 版 |
| 任务层 | legged_lab | `zitongbai/legged_lab`（`pip install -e source/legged_lab`） | 自带 velocity-conditioned AMP 任务（源码有 \|cmd_xy\|<0.06 门控） |
| Python | **3.11** | conda env `-p /data/envs/isaaclab` | Sim 5.x 的 wheel 只有 cp311，硬约束 |
| PyTorch | 2.7.0 + **cu128**（锁 `PIP_CONSTRAINT`，防依赖解析升级破坏 isaacsim 绑定） | | 5.x 官方配套 |
| 硬件 | 9gpu 租用实例：RTX 3090 24G → **RTX 4080S 32G**（2026-10-26 换卡） | Xeon 8350C / 32G 内存 | 换卡后 shader 缓存作废需重编 |
| 系统 | Ubuntu 22.04.4 | 系统盘 59G + 数据盘 200G `/data` | 所有环境装数据盘 |

**版本错配教训**：用 Python 3.10 的 pip 装 5.x 会报 `No matching distribution found for isaacsim==5.1.0`，
且可用版本只列 4.0–4.5 —— 看起来像"5.1 不存在"，实际是平台 wheel 不匹配。
4.5/2.1.0/py3.10 是另一条已验证路线（Poppy 项目在用）。

## 2. 环境搭建（云端，全自动化）

入口：`setup/01_install_env.sh` → `02_install_legged_lab.sh`，60–90 分钟可复现。

### 2.1 磁盘与缓存策略（第一步，错则全盘崩）

- 系统盘只有 59G（剩 26G），Isaac Sim 全量 20GB+，conda env 必须 `-p /data/envs/isaaclab` 建到数据盘
- `~/.cache` 整体软链到数据盘（Kit shader 缓存、pip、warp 都走这里）
- pip 源实测：**平台预置的阿里云镜像索引页快（4MB/s）但文件 CDN 只有 260KB/s**，
  换腾讯云镜像后 18MB 的 wheel 从 68s → 12s。教训：**测文件下载速度，别只测索引页**

### 2.2 安装顺序（不可乱）与四道坑

```
conda tos accept（25.9 的静默拦截）→ 建 py3.11 env → torch 2.7.0+cu128
→ isaacsim[all,extscache]==5.1.0 → clone IsaacLab v2.3.2 → isaaclab.sh --install rsl_rl skrl
→ clone rsl_rl(feature/amp) + pip -e → clone legged_lab + git lfs pull（G1 USD + motion data）
→ pip -e source/legged_lab → 冒烟测试
```

1. **conda 25.9 ToS**：不 `tos accept` 则 `conda create` **静默失败**（只给文档链接），
   后续 activate 失败 → 全部命令跑在系统 Python 3.10 上 → 触发"5.1 不存在"假象
2. **绝不依赖 `conda activate`**（非交互 shell 里静默失败）：全程用 env 的绝对路径
   `/data/envs/isaaclab/bin/python`；让 `isaaclab.sh` 认出 `-p` 建的 env 靠
   `export CONDA_PREFIX=/data/envs/isaaclab`（它优先读这个变量）
3. **EULA 交互提示**：5.x 上只设 `OMNI_KIT_ACCEPT_EULA=YES` 不够，非交互执行会卡死，
   必须 `yes Yes |` 喂 stdin。最阴的点：pip 装完显示成功，只有 `import isaacsim` 时才炸
4. **任务注册自检**：装完 legged_lab 必须 `import legged_lab` 后查 `gym.registry`，
   确认 `LeggedLab-Isaac-AMP-G1-v0` 注册成功（装错版本的症状就是注册表为空）

### 2.3 验收三步（缺一不可）

```bash
python -c "import torch, isaacsim, isaaclab, rsl_rl, warp, gymnasium"   # 1. 包导入
./isaaclab.sh -p scripts/environments/list_envs.py                     # 2. 注册表（100+ env）

```

## 3. 模型与动作数据导入

### 3.1 G1 资产（本项目）：走"现成管线"

- **G1 USD 与已 retarget 的 LAFAN1 动作数据都随 legged_lab 仓库走 git LFS 分发**
  （`git lfs pull` 拉取），宇树官方已完成 LAFAN1 → G1 骨架的 retarget
- 选型时就明确了这个取舍：**跳过 retarget 环节**（自建管线最耗时的部分），
  把预算留给算法与评测
- 参考数据规格：LAFAN1 walk_and_run 子集 **30 段 clip / 总 156s / 30fps**，
  字段含 `dof_pos`（29 DOF）、`root_lin_vel`、`key_body_pos`（**世界坐标**，实测确认：
  idx0/1 z≈0.05 是脚，idx4/5 z≈1.04 是头/手）

### 3.2 数据体检（开训前闸门，`scripts/verify_motion.py`）

retarget 出来的数据"运动学上像"不代表"物理上能做"。体检项：
关节角 vs G1 限位（hip_pitch [-1.05,1.57]、knee [-0.10,2.25] 等，留 25% 余量）、
骨盆高度（站立 0.74m，合理区间 0.55–0.95）、速度区间（走 1.0–1.8 / 跑 2.0–3.5 分档）、
NaN、帧间跳变（p99.9）。**纯 numpy/pandas，不需要起仿真，本地 20 分钟跑完。**

### 3.3 对照经验：Poppy 项目的自建 URDF→USD 管线（面试可讲的深坑）

G1 用的是现成资产；**自建资产的坑是在 Poppy 双足上踩全的**（Isaac Lab 2.1 路线）：

| 坑 | 现象 | 解法 |
|---|---|---|
| URDF 里 `package://meshes/X.STL` | 几何体全丢 | 改相对路径，网格放 `meshes/` |
| **文件名大小写不一致** | Linux 上 `RuntimeError: Used null prim`，资产直接报废 | 转换前做"引用 vs 磁盘文件"集合对比；**Windows/macOS 永远测不出来**（文件系统不区分大小写） |
| **USD 关节限位单位是「度」** | 按弧度读 → 膝盖单向限位失效 → RL 立刻学会反关节作弊解 | UsdPhysics revolute 的 lower/upper 用度；Isaac Lab 内部用弧度（schemas.py 有 ×π/180 的佐证） |
| **驱动刚度单位层间不一致** | 从 USD 抄 `drive:angular:physics:stiffness`（N·m/**deg**）进配置（N·m/**rad**）→ 关节软 57 倍，"能跑但站不住" | 用实验标定：固基座+关重力+已知力矩→稳态偏角反推 kp_eff（实测换算系数 0.951） |
| 转换器默认 `--joint-stiffness 100.0` | 对小型舵机（MX-28 堵转 2.5 N·m）过量几十倍，数值爆炸 | 按 `kp ≈ 堵转力矩/20` 量级起估 |
| 全身自由度全留 | 上身乱甩的退化解 | URDF 里把不参与控制的关节改 `fixed`，`--merge-joints`：实测 **25→10 DOF、26→11 刚体** |

离线核对 USD 不启动 Kit：`pip install usd-core` 后 `from pxr import Usd, UsdPhysics` 直接遍历
（省掉每次 15s+ 的 Kit 启动）。

## 4. 仿真运行配置

- **规模**：4096 并行环境，save_interval=200（监控点必须取 200 的倍数）
- **速度**：≈2.9–4 s/iter（≈15–20 iter/min；与 eval 并发时降到 ~10 iter/min）
  —— 不同时期/硬件实测略有出入，以 run 目录日志为准
- **算法**：PPO + AMP 判别器；奖励混合在 `rsl_rl/modules/amp.py:203`：
  `r = λ·r_task + (1−λ)·r_style`（λ=0.5，legged_lab 默认值，未扫描）
- **判别器观测不含根线速度**（源码级事实）：侧移/后退时"站着不动"不会被风格项扣分
  → 直接解释全向能力边界：行走中左转 90° 达成 82%，侧移/后退/原地转向 ≈ 6%
- **对称性修复（进行中）**：自定义 `leg_work_asymmetry` 奖励
  `EMA(|τ·ω|, tc=1.5s)` 的左右腿不对称惩罚 —— 用机械功率代替 τ²
  （堵 τ² 在等长收缩时虚高、窗口短于步态周期被碎步 exploit 两个漏洞）

## 5. 评测 / 回放 / 远程运维基础设施

| 组件 | 细节 |
|---|---|
| `eval_gait.py` | 确定性 rollout → npz：torque / foot_z / joint_vel / **joint_pos**（后补的，此前姿态类问题无法量化）/ foot_force_z / body_height |
| `gait_metrics2.py` | 迟滞接触判定（防足端抖动被算成多迈一步）+ 髋角自相关交叉验证，**两种算法同数才采信** |
| `watch_v2.py` | 每 400 iter 自动 eval → CSV；两套早停：综合分不改善 + **never-walked**（到点还没走就杀） |
| 视频录制 | `rl-video-step-0.mp4` 会被下次录制覆盖 → 录完立刻另存；headless 下 GLFW 报错是正常噪音 |
| 远程命令 | 走 `exec_file.py` 命令文件（本地 shell 会吃掉 `$`）；**命令文件首行必须是注释**（Write 工具带 BOM 会吃掉第一条命令）；Python 加 `-u` 否则输出缓冲看着像卡死 |
| 进程卫生 | `simulation_app.close()` 会留僵尸进程占显存（实测累积 6 进程/5.2GB）；`pkill -f` 会自杀，用 `pgrep -f "scrip[t]"` + 按 PID kill |
