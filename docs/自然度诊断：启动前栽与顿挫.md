# 自然度诊断：启动前栽、机械感、以及全向行走可行性

> 日期：2026-10-26 ｜ 触发：面试官反馈"还是有点不自然…步幅有问题，一顿一顿，
> 有点匆忙"，并建议改用**单环境**做**全向行走**。
> 本文所有结论都标注强度，源码事实可直接核对。

## 0. 结论速览

| 现象 | 机制 | 强度 | 修法 | 是否需要重训 |
|---|---|---|---|---|
| 开头猛地前栽 | 指令**阶跃**：t=0 时 v=0 而 cmd=1.2，跟踪奖励逼出"全力前倾加速" | **硬**（机制+源码） | 指令**斜坡限幅** | ❌ 不需要 |

## 1. 启动前栽：不是 bug，是训练出来的最优解

### 机制

跟踪奖励是 `exp(-|v - v_cmd|² / 0.25)`（`g1_amp_env_cfg.py:38`，std=√0.25）。
指令在 t=0 的瞬间从 0 跳到 1.2 m/s：

- 误差 1.2 → 奖励 `exp(-5.76) ≈ 0.003`，几乎为零
- 训练时每 10 s 重采样一次，策略反复经历这种阶跃
- 被"尽快消除误差"压着学，学到的最优解就是**全力前倾加速**

所以这个前栽是**学出来的，不是没学会**。t=0 只是这个阶跃的最大化版本
（从完全静止起步），因此每段的开头都最明显。

### 这同时解释了另外两件事

- **随机指令版每次换速都一顿** —— 同一个机制，每 10 s 重演一次
- 之前归因的"多环境视频里机器人最开始站不稳" —— 也是它

（此前我把"最开始站不稳"归因到推搡和随机重采样，那只解释了一部分；
**指令阶跃是另一半，而且是无扰动条件下依然存在的那一半。**）

### 修法：指令变化率限幅（slew rate limit）

把阶跃改成斜坡：`cmd` 每步最多变化 `RAMP_RATE × dt`。

- 零重训，纯部署端
- 真机部署本来就要做指令平滑（Unitree 官方控制器同样对速度指令做 ramp）
- 副作用是好的：转向段之间的过渡也更顺

已实现为 `patch_play_cmd.py` 的 `PIN_MODE=ramp|omni`，并用
`ab_pin12.mp4` vs `ab_ramp12.mp4` 做 A/B 验证。

## 2. 为什么"不像人类自然行走"——数据集的硬缺口

参考动作目录（`legged_lab/data/MotionData/g1_29dof/amp/walk_and_run`）共 **30 个 clip**，
完整分类：

| 类别 | 数量 | 片段 |
|---|---|---|
| 走 + 转弯 | 10 | B9/B10/B11/B13/B14/B15、Walk_B10/B13/B15/B16 |
| 侧步 | 4 | B22/B23、Walk_B22/Walk_B23 |
| 倒走 | 2 | B4、Walk_B4 |
| 跑直线 | 2 | C1（站→跑）、C3（跑） |
| 跑 + 转弯 | 7 | C11–C17 |
| 跑倒退 | 3 | C6/C8/C9 |
| 走跑过渡 | 2 | C4/C5 |

**没有任何一条"匀速直线向前行走"。**

后果：在 0.5–1.5 m/s 这个行走速度段，判别器能匹配的模板只有两类——
①转弯片段（步幅短、带方向调整，天生就不平顺）；
②跑步片段（高步频）。直线慢走这个最常见的展示场景，
恰好落在参考数据的**空档**里。

强度：**硬**（目录级事实，可直接 `ls` 核对）。
但要说明：这是"为什么低速直线最难看"的**结构性解释**，
不等于"补了数据就一定好看"——那是待验证的假设。

## 3. 判别器看不见"走得快不快"

`amp_env_cfg.py:159-176`（agent 侧）与 `179-206`（demo 侧）：

```python
class DiscriminatorCfg(ObsGroup):
    # root_local_rot_tan_norm = ...   ← 注释掉了（躯干朝向）
    base_ang_vel = ...                # 3
    joint_pos    = ...                # 29
    joint_vel    = ...                # 29
    # key_body_pos_b = ...            ← 注释掉了（关键身体点）
```

两侧都只有 **61 维 = 躯干角速度 + 关节角 + 关节角速度**。

**没有根线速度，没有躯干朝向，没有关键身体点位置。**

含义：判别器能判断"姿势像不像人"，但**判断不了这个姿势对应多快的移动**。
于是"用跑步的高步频去走 1.2 m/s"这种组合，在它眼里完全可以得高分——
**"步频与速度的耦合"这个约束，在当前框架里是缺失的**，只能靠任务奖励
间接施加。

强度：**硬**（源码实证）。这条同时是一个可做的消融实验
（把 `ref_root_lin_vel` / `key_body_pos_b` 加回去，看步频是否收敛到人带）。

## 4. 实测：步频到底差多少

`scripts/analyze_cadence.py`，口径见文件头（步长 = v/步频，不乘 2）。
"步频比"= 实测步频 / 同 Froude 数下人类步频（已按腿长 0.68 m vs 0.90 m 缩放）。

| 模型 | 指令 | 实测 v | 步频 Hz | cadence | 步长 m | 人步长 | 步频比 |
|---|---|---|---|---|---|---|---|
| **amp2000**（发给面试官的） | 1.0 | 1.00 | 1.17 | 140 | 0.43 | 0.48 | 1.13 |
| **amp2000** | **1.2** | 1.28 | 1.22 | **146** | 0.53 | 0.57 | **1.07** |
| amp2000 | 1.5 | 1.61 | 1.31 | 157 | 0.62 | 0.69 | 1.12 |
| lam050（λ=0.5） | 1.0 | 0.98 | 1.23 | 147 | 0.40 | 0.48 | 1.20 |
| lam075（λ=0.75） | 1.0 | 1.03 | 1.50 | 180 | 0.34 | 0.49 | **1.43** |
| lam025（λ=0.25） | 1.0 | 0.75 | 1.18 | 142 | 0.32 | 0.40 | 1.27 |
| ppo_baseline（纯 PPO） | 0.5 | 0.40 | 2.11 | 254 | 0.10 | 0.23 | **2.32** |

两条能站住的结论：

1. **AMP 确实比纯 PPO 像人得多**（步频比 2.32 → 1.07–1.43），风格奖励是有效的
2. **λ=0.5 比 λ=0.75 更接近人的步频**（1.07–1.20 vs 1.35–1.43），
   与风格分排序（0.721 vs 0.390）一致 —— 说明风格分这次是真的在反映"像不像人"

**一个必须承认的反面证据**：amp2000 在 1.2 m/s（视频用的速度）步频比只有 **1.07**，
duty 0.57（典型行走），手臂摆幅正常（肩关节角速度 RMS 2.5–3.4 rad/s）。
也就是说**客观步态参数离人类并不远**。面试官说"步幅有问题、匆忙"，
我目前的三个量化指标（步频、duty、摆臂）**没能抓到**。
→ **"顿挫"这个主诉我还没翻译成可证伪量**，这是当前最大的诊断缺口（见 §7）。

强度：**中**。单 seed、1500–2000 iter、6 个离散速度档；排序可信，
绝对值不要写进简历。

### 顿挫的三次尝试与失败

| 尝试 | 结果 |
|---|---|
| 步频/步长（§4） | 能解释"碎步"，但 amp2000 @1.2 只差 7%，解释不了主诉 |
| 速度波动 CV + 自相关周期强度 | 数据噪声大：部分速度档跟踪失败（如 lam025 @2.5 实测 1.66 vs 指令 2.5），CV 被失败样本污染，跨模型不可比 |
| 手臂摆动 | **排除**：肩关节 RMS 2.5–3.4 rad/s，摆臂正常 |

## 5. 全向行走：能力是有的，但部署配置被我改坏了

训练配置（`g1_amp_env_cfg.py:232-235`）：

```
lin_vel_x  = (-0.5, 3.0)     ← 含后退
lin_vel_y  = (-0.5, 0.5)     ← 含横移
ang_vel_z  = (-1.0, 1.0)
heading    = (-π, π)
heading_command = True       ← amp_env_cfg.py:79 的默认
```

**横移、后退、转向都在训练分布内**，不需要重训。

但 PLAY 配置被我（10-22 为了录直走）改成：

```
heading_command = False
ranges.ang_vel_z = (0.0, 0.0)
ranges.lin_vel_y = (0.0, 0.0)
```

两个问题：

1. **模式不匹配**：训练用 heading 模式（cmd[2] 是朝向误差经 P 控制器闭环得出，
   会自然衰减到 0），部署用 yaw-rate 模式（cmd[2] 是目标角速度，恒定不衰减）。
   录直走时两者都是 0，看不出差别；**一旦要转向就分布外**。
2. **更致命**：`ranges.ang_vel_z = (0.0, 0.0)`。heading 模式下
   `cmd[:,2] = clip(k × 朝向误差, ang_vel_z[0], ang_vel_z[1])`——
   **裁剪区间是 (0,0)，转向指令恒为 0，物理上根本转不动。**

修法（`patch_play_cmd.py` v3 已做）：运行时把 `heading_command` 改回 True、
`ang_vel_z` 范围还原为 (-1,1)、`rel_heading_envs=1.0`，
并按脚本设置 `heading_target = 当前朝向 + 该段转角`，
**转向的闭环交给 command manager 自己算** —— 这样指令的时间演化与训练完全一致。

### 关于"取最优 demo"

多环境是为了展示泛化；单环境可以只挑最好的一条——**这是行业常规做法**，
但有一条红线：可以挑最好的一条当 demo，**不能用它去声称"典型表现"**。
对外表述必须是"best-of-N 展示"，中位数/失败率另算。
