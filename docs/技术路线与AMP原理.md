# 技术路线与 AMP 原理

> 目标：用 AMP（Adversarial Motion Priors）让宇树 G1 在 Isaac Lab 中做出**拟人态走跑**，
> 替代此前"PPO + 手写奖励"那种能走但僵硬的步态。
> 最后更新：2026-10-19 17:10

---

## 1. 为什么是 AMP：问题的本质

### 1.1 手写奖励的天花板

PPO 做双足行走的常规做法是手写一堆奖励项：

```
r = w1·(速度跟踪) + w2·(别摔倒) + w3·(关节别超限) + w4·(能耗小) + w5·(脚抬够高) + ...
```

问题在于"好看的步态"是个**高维、难以逐条列举**的性质。你能想到的项（步频、步长、抬脚高度）
只是冰山一角，真正决定观感的是整条轨迹的**分布特征**——手臂摆动与腿的相位关系、
落地时重心的起伏节奏、躯干的微小扭转。这些既列不全，权重也无从推导，
只能靠实验试错。结果是收敛到一个"每一项都勉强及格、整体很机械"的局部最优。

### 1.2 AMP 的思路转变

**不定义什么叫好看，改为让判别器从数据里学。**

给一批真人动捕数据（LAFAN1，已 retarget 到 G1 骨架），训一个小网络 D 去区分
"这段关节运动来自真人还是来自机器人"。策略的奖励里加一项：

```
r_style = -log(1 - D(s_t, s_{t+1}))
```

判别器越觉得像真人，策略拿到的分越高。判别器自己在训练中不断变强，
策略就得越来越像才能骗过它——这就是对抗。

**关键差异**：手写奖励只能惩罚你**想到了**的特征；判别器惩罚的是**数据里真实存在**的
全部统计特征。所以它天然能覆盖你列不全的那些细节。

## 2. 判别器在学什么（数学）

### 2.1 输入是 4 帧历史窗口，不是单帧

**本项目实测**（从训练的 discriminator 网络结构反推确认）：

```
disc 观测组 shape = (4, 61)
    每帧 61 维 = base_ang_vel(3) + joint_pos(29) + joint_vel(29)
    4 帧历史拼接 → 判别器输入 244 维

判别器网络：Linear(244→1024) → ELU → Linear(1024→512) → ELU → Linear(512→1)
```

判别器看的是**连续 4 帧的关节运动历史**。原因很直接：单帧只能判断
"这个姿势人类能否做到"，多帧才能判断"这个**运动过程**是否人类风格"。
一个僵硬机器人可以摆出和人类一样的静态姿势，但姿势之间的**变化方式**会露馅。

输入里**不含世界坐标的绝对位置**（没有 root 全局位置/朝向），
只有角速度、关节角、关节速度——这样学到的才是**风格本身**，
而不是"在场地某个角落走路"。

> 注：Peng 原论文里判别器输入是两帧 transition，本文摘要写的也是 `(s_t, s_{t+1})`。
> legged_lab 的实现用了 4 帧窗口。**面试时按本项目的实际情况讲（4 帧 / 244 维），
> 别讲错成两帧**——这是文档早期版本留下的错误，已根据实测网络结构修正。

### 2.2 训练目标：最小二乘 GAN

AMP 原文（Peng et al., 2021）用的是 LSGAN 形式，比原始 GAN 的梯度更稳定：

```
判别器损失：
  L_D = E_参考[(D(s,s') - 1)²] + E_策略[(D(s,s') + 1)²] + w_gp · E_参考[‖∇D‖²]

风格奖励：
  r_style = -log(1 - D(s,s'))     （D→1 时奖励→+∞，D→0 时奖励→0）
```

第三项是**梯度惩罚**（gradient penalty），防止判别器在参考样本附近变得陡峭，
这是 GAN 训练里对抗模式崩塌的标准手段。

### 2.3 两个网络的更新节奏

- 策略（actor-critic）用 PPO 更新，采样来自 4096 个并行环境
- 判别器用 Adam 独立更新，正负样本分别来自**参考动作库**和**当前策略的 rollout buffer**
- 两者交替；判别器通常需要每轮多更新几次才能跟上策略的变化

## 3. AMP vs DeepMimic（面试高频追问）

| 维度 | DeepMimic | AMP（本项目） |
|---|---|---|
| 参考数据用法 | 逐帧目标姿态，需**相位变量** phase 对齐 | 只做分布匹配，**不需要 phase** |
| 奖励 | 显式姿态跟踪误差 ‖q − q̂‖² | 判别器输出的风格分 |
| 多动作切换 | 一条 clip 一个策略；切换需额外门控 | 多 clip 共用一个判别器，按速度指令自动选风格 |
| 保真度 | 高（几乎复刻参考动作） | 略低（只匹配分布，不逐帧对齐） |
| 泛化性 | 弱 | 强——这是我们选它的原因 |

**为什么不需要 phase 很重要**：phase（"现在走到周期的第几拍"）是 DeepMimic 类方法的
硬前提，一旦要做走↔跑切换、变速，phase 的对齐和插值就变成一团麻烦事。
AMP 靠"速度指令 + 判别器"的组合，让策略自己学会"要跑快点时该摆成什么样"。

本项目用的 `LeggedLab-Isaac-AMP-G1-v0` 奖励里**同时**包含：
- `track_lin_vel_xy_exp` / `track_ang_vel_z_exp`——速度指令跟踪（任务）
- `style`——判别器风格分（风格）

所以它能按命令切换走/跑，这是纯模仿方案做不到的。

## 4. 数据链路

```
LAFAN1（真人动捕 BVH）
    ↓  retargeting：人体骨架 → G1 29 DOF 骨架
G1 关节角序列（.pkl）
    ↓  打包
/data/legged_lab/MotionData/g1_29dof/amp/walk_and_run/   ← 26 段
    ↓
训练时两条用途：
  ① 判别器随机采样连续两帧 → 正样本
  ② episode 起始状态从参考动作中抽取 → 加速早期探索（reference state initialization）
```

**本项目跳过了 retarget 环节**：`legged_lab` 仓库用 `git lfs pull` 自带了宇树 G1 的
USD 模型（29 DOF，103 MB）和已 retarget 好的动作数据。这省掉了全流程里最容易
卡两天的步骤，也是 2 天能出结果的决定性因素之一。

参考动作构成（实测，共 **30 段**，合并为一个 motion dataset，**总时长 156 秒**）：

| 类别 | 片段 |
|---|---|
| 行走类 (9) | walk turn left/right 45/90/135、walk turn around、side step L/R、stand→walk backwards |
| 跑步类 (14) | run turn L/R 45/90/135、stand→run、run to walk、**walk to run**、run change direction、run backwards 系列 |
| Walk 前缀扩展 (7) | 更慢的常速行走、侧步、转身、后退 |

**"拟人态走跑"的关键就在这里**：`walk_to_run`、`run_to_walk`、`walk_turn_*`
这些**过渡片段**都在同一个动作库里。策略不是分别学"走"和"跑"两个模式，
而是在同一个判别器的分布约束下学会连续变化——这才有资格叫"拟人态走跑"，
而不是"两个独立步态硬切换"。

## 5. 技术选型（决策表）

| 决策点 | 选择 | 备选 | 为什么 |
|---|---|---|---|
| 框架 | `legged_lab` | `humanoid_amp`（保底） | legged_lab 的 AMP **带速度指令**，能按命令切换走/跑；自带 G1 USD + 已 retarget 动作 |
| 机器人 | 宇树 G1（29 DOF） | H2 | GMR 等 retarget 工具目前不支持 H2；G1 生态最全，2 天内出结果概率最高 |
| 参考数据 | LAFAN1 retarget 版 | AMASS + GMR 自处理 | 省掉 retarget 环节；AMASS 作为后续增强备选 |
| RL 后端 | rsl_rl（AMP fork） | skrl | legged_lab 主线就用 rsl_rl |
| Sim 版本 | Isaac Sim **5.1.0** | 4.5 | IsaacLab v2.3.2 硬要求 Sim 5.x；5.x wheel 只有 cp311 |
| Lab 版本 | IsaacLab **v2.3.2** | — | legged_lab 锁定版本 |

**版本锁**（改任何一个都会连锁崩）：
```
Python 3.11.17  →  torch 2.7.0+cu128  →  isaacsim 5.1.0  →  IsaacLab v2.3.2
```
其中 torch 版本是硬约束：isaacsim 5.1 按 torch 2.7 编译，
pip 解析依赖时曾试图拉 torch 2.14.1 + CUDA 13 覆盖它（已用 `PIP_CONSTRAINT` 锁死）。

### 6.0 任务配置实测（日志 dump，面试可直接引用）

**观测空间**

| 组 | 维度 | 构成 |
|---|---|---|
| policy | **495** | 5 帧历史 ×(角速度 3 + 根部朝向 6 + 速度指令 3 + 关节角 29 + 关节速度 29 + 上一步动作 29) |
| critic | **600** | policy 全部 + 根部线速度(15) + 关键刚体位置(90)——**非对称 actor-critic**，评论家能看到策略看不到的真值 |
| disc | **4×61** | 4 帧历史 ×(角速度 3 + 关节角 29 + 关节速度 29) |
| disc_demo | **4×61** | 同结构，但来自参考动作（关节角/速度是目标值） |

> "非对称"这一点很关键：critic 知道真实的根部线速度和关键点位置，
> actor 不知道。这让价值估计更准，而部署时不需要这些真值——标准的
> **教师-学生式特权信息**设计。

**奖励权重（实测表）**

| 奖励项 | 权重 | 作用 |
|---|---|---|
| `track_lin_vel_xy_exp` | 1.0 | 跟踪前进/横移速度指令 |
| `track_ang_vel_z_exp` | 1.0 | 跟踪转向指令 |
| `flat_orientation_l2` | −1.0 | 躯干保持水平 |
| `lin_vel_z_l2` | −0.2 | 抑制上下颠簸 |
| `ang_vel_xy_l2` | −0.05 | 抑制躯干翻滚/俯仰抖动 |
| `dof_torques_l2` | −2e−6 | 能耗惩罚（权重极小，几乎只做正则化） |
| `dof_acc_l2` | −1e−7 | 抑制关节抖动 |
| `action_rate_l2` | −0.005 | 抑制动作突变，让输出平滑 |
| `dof_pos_limits` | −1.0 | 关节别撞限位 |
| `joint_deviation_hip / arms / waist` | −0.1 / −0.05 / −0.1 | 别偏离默认姿态太多 |
| `feet_air_time` | 0.5 | 鼓励腾空步态 |
| `feet_slide` | −0.1 | 抑制拖脚（这就是 PPO 手搓时"走路擦地"的对症药） |
| `termination_penalty` | **−50.0** | 摔倒重罚，权重最大 |
| **`style`（AMP）** | 独立注入，不在此表 | 判别器风格奖励 |

**注意最后一行的含义**：`style` 不在 Reward Manager 的 15 项里，
它由判别器单独计算后注入总回报。**这正好印证了第 1 节的观点**——
任务侧只有这些"能不能走"的项（而且 `feet_air_time`、`feet_slide` 已经是
很勉强的观感项），**"好不好看"完全交给判别器**，这才是 AMP 的精髓。

**域随机化 / 扰动（实测）**

| 项 | 配置 |
|---|---|
| `push_robot` | 每 5 秒给机器人一次外部推力（训练抗扰动鲁棒性） |
| `physics_material` | startup 时随机化摩擦/弹性 |
| `add_base_mass` | startup 时给基座随机附加质量 |
| `base_external_force_torque` | reset 时随机施加外力矩 |
| `reset_from_ref` | **episode 起始状态从参考动作中采样**（reference state initialization，大幅加速早期探索） |

### 6.1 训练曲线实测

> ⚠️ **本节结论已被更正（10-20）**，原文保留未删。
> 当时只看了 iter 400 与 iter 2000 两个点，得出"style 还在稳步上升、任务与风格没有打架"的判断。
> 解析完全部 5000 轮后事实相反：**风格分在 iter 2000 达峰 0.797，之后单调回落至 0.602**，
> 而同期任务指标（跑满全程 95.6%→95.9%）几乎没再提升 —— 策略在后期牺牲了风格。
> 完整数据与更正对照见 [训练曲线分析.md](./训练曲线分析.md)。

**@ iter 400（17:02）**

| 指标 | iter 400 | iter 2000（18:00） | 读法 |
|---|---|---|---|
| `Episode_Reward/style` | 0.662 | **0.788** | 判别器给的"像人"评分在涨 ✅ |
| `track_lin_vel_xy_exp` | 0.145 | **0.710** | 速度跟踪大幅改善（满分 1.0） |
| `track_ang_vel_z_exp` | 0.183 | 0.367 | 转向跟踪进步明显 |
| `error_vel_xy` (m/s) | 2.13 | **0.615** | 速度跟踪误差降了 71% |
| `Termination/time_out` | 0.602 | **0.953** | 95% 的 episode 能跑满全程 ✅ |
| `Termination/base_height` | 0.323 | **0.0126** | 重心过低摔倒率 32%→1.3% ✅ |
| `Termination/bad_orientation` | 0.093 | 0.036 | 姿态崩 9.3%→3.6% ✅ |
| `Mean reward` | — | 17.95 | — |
| `Mean episode length` | — | 980.9 | 接近满长度（1000 步） |
| `Mean action noise std` | — | 0.40 | 策略仍有探索空间 |

**判别器分**（iter 2000）：`disc_score −0.551` / `disc_demo_score +0.556`。
两者符号相反且绝对值接近，说明判别器**还能把两者分开**（尚未被完全骗过），
这是健康的对抗状态——若两者趋同则说明判别器已经失效、策略在钻空子。

**判读**：400→2000 迭代之间，摔倒率从 **40% 降到 4.6%**，速度跟踪从 0.145 涨到 0.71，
同时 style 还在稳步上升。三者同时改善说明任务奖励和风格奖励**没有互相打架**——
这是 AMP 训练最容易出问题的地方（风格太强会跑不稳，任务太强会牺牲风格），
目前权重配比是合适的。
