## 2. 证据链修正：把 v1/v2/v2.1 摆在一起看，之前的结论要降级

| iter | **v1**（学会了） | v2 | v2.1 | v2.2 |
|---|---|---|---|---|
| 400 | v_act **0.06** | 0.06 | 0.07 | — |
| 800 | v_act **0.97** ✅ | 0.06 ❌ | 0.05 ❌ | — |
| 1200 | 1.04 | — | 0.07 ❌ | — |
| 1600 | 1.01 | — | — | — |
| 2400 | 0.99 | — | — | — |

**关键事实：v1 在 iter 400 时也只有 0.06。**"学会走路"是 400→800 之间的**相变**，
不是线性爬升。

这直接动摇了之前"排除法定罪 `leg_work_asymmetry` 权重 −2.0"的证据强度：

| 原结论 | 原证据 | 现在的评级 |
|---|---|---|
| v2 没学会走路 | iter 800 时 v_act 0.06，而 v1 同期 0.97 | **成立**，但 v2 只训到 800 就被人为杀掉，正好卡在相变区间 |
| v2.1 也没学会 | iter 1200 时 0.07，而 v1 同期 1.04 | **较强**（v2.1 撑过了相变窗口仍未起飞） |
| 主因是权重 −2.0 | v2.1 回退 ang_vel 后仍失败 → 排除法 | **降级为"嫌疑"**。真正的机制更可能是"约束在形成期压死探索"，与权重的**具体数值**关系没那么大 |
| v2.2 用 −1.0 会成功 | 无 | **无证据**（没跑过） |

**一句话**：不是"数值没调对"，是"**根本没给够形成期**"。
这也正好对上教训 3.6（约束必须在 motor primitive 形成期施加）和
3.9（惩罚项零点=站着不动，早期重罚会把人推向不动）。

## 4. v2.3：一个源码，两种跑法

补丁只改一处——在 `leg_work_asymmetry` 的返回值上乘一个 0→1 的线性斜坡：

```python
# rewards.py（已应用）
_V23_WARMUP_STEPS = int(os.environ.get("LEG_ASYM_WARMUP_STEPS", "12000"))

def _v23_warm_scale(env) -> float:
    n = _V23_WARMUP_STEPS
    if n <= 0:
        return 1.0                      # WARMUP=0 -> 完全退化成 v2.2
    c = int(getattr(env, "_v23_reward_calls", 0)) + 1
    setattr(env, "_v23_reward_calls", c)
    return min(1.0, c / float(n))       # 前 n 个控制步线性爬升

# 函数末尾
return rel.mean(dim=-1) * _v23_warm_scale(env)
```

设计上的两个取舍：

1. **自己数调用次数，不用 `env.common_step_counter`**。reward 每个控制步调一次，
   自计数零依赖 Isaac Lab 内部属性，不会因为版本改名就崩（同文件已有
   `_leg_work_asym_ema` 这种 setattr 写法，风格一致）。
2. **斜坡控制在 500 iter（12000 步 = 24 steps/iter × 500）**。v1 的相变在 400–800，
   所以让惩罚在相变前后逐步到位，而不是一上来就满额。

### 4.1 两种跑法

```bash
# 主线：v2.3（warmup 12000 步）
bash setup/37_train_fresh_v23.sh

# 对照组：纯 v2.2 复跑（等价于 10-27 那轮没跑完的配置）
WARMUP=0 bash setup/37_train_fresh_v23.sh

# 快速探针：只看早期能不能起飞（约 50 分钟）
MAX_ITER=1200 bash setup/37_train_fresh_v23.sh
```

**为什么建议先跑对照组（WARMUP=0）**：v2.2 从没跑到 800 iter 这个相变窗口，
它是"唯一没被真正检验过的配置"。先花 1 小时给它一个公平机会，
如果它也起飞，说明之前三轮全是"杀早了"，warmup 根本不需要。

**但你的排期是晚上挂机**，所以更实际的做法是：**直接跑 v2.3（warmup）**，
把对照组留作后手。warmup=0 时惩罚从一开始就满额，而这个条件已经被 v2.1
（跑到 1200 仍未起飞）证伪过一次。

## 5. 切卡后的执行顺序

| 步 | 动作 | 耗时 | 判据 |
|---|---|---|---|
| 1 | `nvidia-smi` 确认卡挂上了 | 10 s | 有卡型号输出 |
| 2 | 起 v2.3 + watch：<br>`nohup bash setup/37_train_fresh_v23.sh > /dev/null 2>&1 &`<br>`nohup python scripts/watch_v2.py &`（`WATCH_CSV=/data/progress/v23_curve.csv`） | 2 min | 日志出现 `warmup=12000` |
| 3 | 等 iter 400（约 20 min）看第一个评估点 | — | **v_act ≥0.2 有戏；<0.1 危险** |
| 4 | iter 800（约 40 min）再判一次 | — | **v_act ≥0.7 = 起飞**（v1 就在这个点起飞的） |
| 5 | 若 iter 800 仍 <0.2 | — | never-walked 早停会在 iter 1200 杀掉，不用守着 |
| 6 | 跑满后 | — | `full_eval.py` 出全指标 + 录视频 |

**判定阈值表（沿用之前定的）**

| iter 400 的 v_act | 含义 | 动作 |
|---|---|---|
| ≥0.70 | 比 v1 还快 | 让它跑完 |
| 0.20–0.70 | 在爬坡 | 让它跑完 |
| <0.20 | 还没起飞 | 看 iter 800；到 1200 还不动就是失败 |

| 风险 | 处理 |
