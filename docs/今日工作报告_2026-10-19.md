## 2. 技术原理（大白话版）

### 2.1 先说清楚：为什么原来那个 PPO 会"丑"

> **大白话**：PPO 本身没问题，问题出在"我们怎么告诉它什么叫好看"。

常规做法（也就是你之前 Poppy 的路子）是手写一堆奖励项：

```
r = w1·(速度跟上了吗) + w2·(别摔倒) + w3·(关节别扭到) + w4·(省电) + w5·(脚抬够高) + ...
```

每一项都得你自己想到、自己定权重。但"好看的步态"是个**高维且列不全**的性质：

- 你能想到的（步频、步长、脚抬多高）只是冰山一角；
- 真正决定观感的是**整条轨迹的分布特征**——手臂摆动和腿的相位关系、落地时重心起伏的节奏、躯干那点微妙的扭转；
- 这些既列不全，权重也无从推导，只能试。

**结果**：策略会收敛到一个"每一项都勉强及格、整体很机械"的局部最优。更致命的是，它倾向于收敛到**单一极限环**——速度指令一变，它就在同一个步态模式上拉伸，看起来就像机器在滑行，不像人在换步态。

### 2.2 AMP 的思路转变：不定义"好看"，让判别器从数据里学

> **大白话**：与其费劲描述"什么叫像人"，不如直接拿一堆真人动捕数据，训一个"鉴伪员"去分辨"这段动作是人的还是机器人的"，然后让机器人去骗过这个鉴伪员。

这就是 AMP（Adversarial Motion Priors，对抗运动先验，Peng et al. 2021）。

```
        ┌──────────────────────────────┐
        │  参考动作库（真人动捕）        │
        │  LAFAN1 → retarget 到 G1 骨架 │
        └──────────┬───────────────────┘
                   │ 采样 4 帧窗口 → 正样本（"这是人"）
                   ↓
   ┌───────────────────────────┐
   │  判别器 D（鉴伪员）         │  ← 也在不断变强
   │  Linear(244→1024)→(512)→1 │
   └───────────────────────────┘
        ↑                    ↓
  策略 rollout          风格分 r_style
  （负样本）                  ↓
        ↑              合成总奖励 → PPO 更新策略
        └─────────────────────┘
```

**关键差异**：手写奖励只能惩罚你**想到了**的特征；判别器惩罚的是**数据里真实存在的全部统计特征**。所以它天然能覆盖你列不全的那些细节。

### 2.3 判别器到底在看什么（本项目的实测结构）

这是面试最容易被追问、也最容易讲错的一点，务必按实测讲：

```
判别器输入：4 帧历史窗口 × 61 维 = 244 维
  每帧 61 维 = 躯干角速度(3) + 关节角(29) + 关节速度(29)

判别器网络：Linear(244→1024) → ELU → Linear(1024→512) → ELU → Linear(512→1)
```

三个要点，每一条都能单独讲：

| 要点 | 说明 |
|---|---|
| **看 4 帧而不是 1 帧** | 单帧只能判断"这姿势人能不能做到"，多帧才能判断"这个**运动过程**是不是人的风格"。僵硬机器人能摆出和人类一样的静态姿势，但姿势之间的**变化方式**会露馅 |
| **不含世界坐标绝对位置** | 输入里没有 root 的全局位置和朝向，只有角速度/关节角/关节速度。这样学到的才是**风格本身**，而不是"在场地某个角落走路" |
| ⚠️ 别讲成 2 帧 | Peng 原论文摘要写的是 `(s_t, s_{t+1})` 两帧 transition，但 **legged_lab 的实现用了 4 帧窗口**。本项目实测是 4 帧 / 244 维，面试按这个讲 |

### 2.4 判别器怎么训练：最小二乘 GAN

```
判别器损失：
  L_D = E_参考[(D - 1)²] + E_策略[(D + 1)²] + w_gp · E_参考[‖∇D‖²]
         └ 真人样本打 1     └ 机器人样本打 -1    └ 梯度惩罚

风格奖励：
  r_style = -log(1 - D(s, s'))     D→1（像人）时奖励爆炸式变大，D→-1 时趋近 0
```

> **大白话**：判别器想把真人判成 +1、机器人判成 -1；策略想让自己被判成 +1。两个网络互相抬杠，谁也不停，策略就得越来越像人。
>
> 第三项**梯度惩罚**是 GAN 训练的标准手段，防止判别器在参考样本附近变得过于陡峭导致训练崩掉。用最小二乘（平方误差）而不是原始 GAN 的交叉熵，是为了梯度更稳定。

### 2.5 任务和风格怎么合成一个奖励

这是 AMP 的第二个核心旋钮，也是你明天做消融实验的抓手：

```
r_final = (1 - λ) · r_task + λ · r_style

  r_task：15 项手写奖励（速度跟踪、别摔倒、省电……）—— 保证"能走"
  r_style：判别器给的风格分                        —— 保证"好看"
  λ = task_style_lerp，本项目当前设 0.5
```

- λ ↑ → 更像人，但可能站不稳、跟不上速度指令
- λ ↓ → 更稳，但退回"能走但僵硬"的老路

**这正好印证了第 2.1 节的观点**：任务侧只有"能不能走"的项，而"好不好看"完全交给判别器。看实测的奖励表更能体会这一点——15 项任务奖励里，连 `feet_air_time`（鼓励腾空）和 `feet_slide`（别拖脚）都已经是相当勉强的观感项了，真正的观感全在判别器那。

### 2.6 AMP vs DeepMimic（面试高频追问）

| 维度 | DeepMimic | AMP（本项目） |
|---|---|---|
| 参考数据用法 | 逐帧目标姿态，需要**相位变量 phase** 对齐 | 只做分布匹配，**不需要 phase** |
| 奖励 | 显式姿态跟踪误差 ‖q − q̂‖² | 判别器输出的风格分 |
| 多动作切换 | 一条 clip 一个策略，切换需额外门控 | 多 clip 共用一个判别器，**按速度指令自动选风格** |
| 保真度 | 高（几乎复刻参考动作） | 略低（只匹配分布，不逐帧对齐） |
| 泛化性 | 弱 | **强——这是我们选它的原因** |

**为什么"不需要 phase"很重要**：phase（"现在走到周期的第几拍"）是 DeepMimic 类方法的硬前提。一旦要做走↔跑切换、变速，phase 的对齐和插值就变成一团麻烦事。AMP 靠"速度指令 + 判别器"的组合，让策略自己学会"要跑快点时该摆成什么样"。

本项目用的任务 `LeggedLab-Isaac-AMP-G1-v0` 奖励里**同时**包含 `track_lin_vel_xy_exp`（跟速度）/ `track_ang_vel_z_exp`（跟转向）/ `style`（风格分），所以它能按命令切换走跑——这是纯模仿方案做不到的。

### 3.3 数据链路

```
LAFAN1（真人动捕 BVH）
    ↓  retargeting：人体骨架 → G1 29 DOF 骨架
G1 关节角序列（.pkl）
    ↓  打包成 motion dataset
/data/legged_lab/MotionData/g1_29dof/amp/walk_and_run/   ← 30 段，总时长 156 秒
    ↓
训练时的两条用途：
  ① 判别器随机采样连续 4 帧 → 正样本
  ② episode 起始状态从参考动作中抽取（reference state initialization）
```

**参考动作构成（实测，共 30 段）**

| 类别 | 内容 |
|---|---|
| 行走类 (9) | walk turn left/right 45/90/135、walk turn around、side step L/R、stand→walk backwards |
| 跑步类 (14) | run turn L/R 45/90/135、stand→run、**run to walk**、**walk to run**、run change direction、run backwards 系列 |
| Walk 前缀扩展 (7) | 更慢的常速行走、侧步、转身、后退 |

**"拟人态走跑"的关键就在这里**：`walk_to_run`、`run_to_walk` 这些**过渡片段**和走、跑片段混在同一个动作库里。策略不是分别学"走"和"跑"两个孤立模式，而是在**同一个判别器的分布约束下**学会连续变化——这才有资格叫"拟人态走跑"，而不是"两个步态硬切换"。

> 第 ② 条用途（episode 起始状态从参考动作采样）也值得一提：它让早期探索直接从"接近人样的状态"出发，而不是从随机姿态瞎撞，大幅加速了早期学习。

| 2.5 m/s | 0.792 | 4.03 | 0.222 | 0.586 ⚠️ | 0.800 | 0.948 ⚠️ |
| 3.0 m/s | 1.250 | 4.71 | 0.338 | **0.377** | 0.797 | 0.177 |

⚠️ 2.5 m/s 那档有 6 秒的个别环境失速（分段速度 0.00 → 1.90 → 2.45 → 2.03），平均值不可信。其余 5 档误差都在 0.08-0.18 m/s。

### 4.2 最关键的一条：支撑占比随速度单调下降

```
0.5 m/s  ████████████████  0.751   ← 大部分时间两脚轮流撑地，明显的"走"
1.0 m/s  ██████████████    0.647   ← 人类步行典型值 ≈ 0.60
1.5 m/s  ███████████       0.517
2.0 m/s  ██████████        0.452   ← 明显腾空相出现
3.0 m/s  ████████          0.377   ← 人类跑步典型值 ≈ 0.35，几乎重合
```

**这是整个项目最有说服力的证据。** 它说明策略不是在"走模式"和"跑模式"之间硬切换——那样的话 duty factor 会是两段台阶状突变——而是学会了一条**随速度连续变化**的 gait family，与人类的 walk-run transition 同构。

这直接回应了面试官那句"有点丑"：PPO 手搓版本根子上是**收敛到单一极限环**，速度一变就在同一个极限环上拉伸；AMP 让策略学的是**一族 gait**，随需求连续变形。

### 4.3 与人类参考值对比（诚实版）

| 指标 | 本项目 @1.0 | 人类步行典型 | 本项目 @3.0 | 人类跑步典型 |
|---|---|---|---|---|
| 支撑占比 | 0.647 | ≈ 0.60 ✅ | 0.377 | ≈ 0.35 ✅ |
| 步频 (steps/s) | 0.81 | ≈ 1.8 | 1.25 | ≈ 2.7 | ↓ 偏低 |
| 步长 (m/stride) | 2.38 | ≈ 1.4 | 4.71 | ≈ 2.2 | ↑ 偏大 |
| CoT | 0.535 | ≈ 0.2 | 0.797 | ≈ 0.4 | ↑ 偏高 |

**必须说清的三点偏差（面试时主动说，比被问出来强）**：

1. **步频偏低 / 步长偏大** —— 这部分有**方法论不确定性**。触地判定用"足端高度低于阈值"，阈值敏感；若抬脚初期有短暂回落被误判成触地，步数会被少计，进而放大步长。这两个数**趋势可信，绝对值不要直接引用**。相对而言**支撑占比几乎不受阈值影响**（它是时间比例，不是计数），所以 §4.2 的结论是硬的。
2. **CoT 偏高** —— AMP 类方法的通病，也是诚实的预期结果：判别器要的是"像"，不是"省"。如果把它当缺点讲，正好能接上"下一步改什么"——在奖励里加一项能耗惩罚做多目标权衡。
3. **人类参考值是文献典型量级，不是本项目实测** —— 没放人类实测数据进来对比。面试时说"文献量级"，不要说"人类实测值"。

| # | 现象 | 真凶 | 解法 / 规律 |
|---|---|---|---|
| 1 | `No matching distribution found for isaacsim==5.1.0`，可用版本只到 4.5 | conda 25.9 需先接受服务条款，`conda create` **静默失败** → activate 失败 → pip 用的是系统 Python 3.10，看不到 cp311 的 5.x wheel | 先 `conda tos accept`；**脚本里永远用 env 绝对路径的 python/pip，不要依赖 `conda activate`（失败是静默的）** |

| 3 | pip 显示全部 Successfully installed，但 `import isaacsim` 报 `EOF when reading a line` | Omniverse Kit 首次启动交互式询问 EULA，非交互 SSH 环境 stdin 直接 EOF | `yes Yes \| python -c "import isaacsim"`。规律：**凡"pip 成功但 import 失败"，先看报错里有没有交互提示符** |
| 4 | `isaaclab.sh --install rsl_rl skrl` 报 `Invalid argument provided: skrl` 直接退出 | 该脚本只接受**一个**框架参数 | skrl 直接 `pip install skrl`，不走 isaaclab.sh |

| 6 | isaaclab_rl 依赖解析中 pip 想拉 **torch 2.14.1 + cu13**，会摧毁 isaacsim 的 torch 2.7 绑定 | pip 依赖解析"好心办坏事" | 全程 `export PIP_CONSTRAINT=<锁版本文件>`。规律：**凡 pip install 之后必验 torch 版本** |
| 7 | `create_empty.py --headless` 卡死 **73 分钟**，GPU 显存反而下降，`timeout 900` 的 SIGTERM 被吞 | Kit 冷启动的 shader/JIT 编译在 CPU 上忙等（CPU 152% = busy，非 idle） | 排查套路：**先看 CPU 是 busy 还是 idle**（busy=编译/计算，idle=等网络）；再用 `ss -tnp` 确认有无外部连接，两步定位方向。清理必须用 `kill -9` 按 PID |

| 9 | 监控轮询报"still running"直到 15:04 超时才报警，**浪费 2.5 小时** | DEAD 判据只看进程数，某些时序下 `ps \| grep -c` 误报存活 | 判据加第二条：**日志 mtime 超 5 分钟没更新即判死**。远程任务监控必须"进程数 + 日志活跃度"两个信号都看 |
| 10 | 训练刚结束立刻起新 Kit 进程 → CPU 927% 忙等、GPU 0%、日志 10 分钟无更新 | 训练刚结束时系统状态下新 Kit 初始化易卡 | **训练刚结束别立刻开新 Kit 进程**；带 `--video` 的离屏渲染路径反而全程正常（GPU 38%）。本次处置：等 10 分钟后杀掉，改保视频 |
