## 3. 核心发现：风格分在 iter 2000 之后单调回落

```
风格分
0.80 ┤                    ●2000  0.797  ← 峰值
0.75 ┤        ●1000 ●1500      ●2400
0.70 ┤  ●600         ●1600 ●3000 ●3200
0.65 ┤                              ●3400 ●4000
0.60 ┤                                          ●4999  0.602
     └────────────────────────────────────────────────→ iter
       0     1000    2000    3000    4000    5000
```

**三个事实要一起看：**

1. **风格分**：iter 0→2000 从 0.02 冲到 0.797；iter 2000→4999 回落到 0.602，**跌了 24.4%**。
2. **任务能力**：跑满全程 95.55% → 95.85%（几乎没变），速度误差 0.660 → 0.712（**还略微变差了**）。
3. **总回报**：17.96 → 18.71，涨了 4%。

合起来的含义：**多训 3000 轮，任务能力几乎没有换来提升，风格却明显退化。**
这是 AMP 训练里典型的后期现象。

### 为什么会这样：判别器和策略的军备竞赛失衡

| 指标 | iter 2000 | iter 4999 | 变化 |
|---|---|---|---|
| 判别器分（策略样本） | −0.548 | **−0.677** | 越负 = 判别器越确信"这是机器人" |
| 判别器分（参考样本） | 0.551 | **0.678** | 越正 = 判别器越确信"这是真人" |

两个分数的绝对值**都在变大**——说明判别器全程一直在变强，它总能找到新的角度区分两者；
而策略要同时满足"跟得上速度指令 / 别摔倒 / 省电 / 像人"四个目标，风格排在末位。
策略选择了保任务、放弃风格，这正是 **reward hacking 的一种软形态**——不是钻漏洞，
而是在多目标里挑性价比最高的那个卷。

> 大白话：判别器像个越来越严格的评委，策略发现自己再怎么努力也讨不到好，
> 就干脆把力气花在"不摔倒、跟得住速度"这些确定性收益上，风格分自然掉。

## 4. 对交付的直接影响：选哪个 checkpoint

| | `model_2000` | `model_4999` |
|---|---|---|
| 风格分 | **0.797** | 0.602 |
| 跑满全程 | 95.55% | 95.85% |
| 速度跟踪误差 | **0.660 m/s** | 0.712 m/s |
| 摔倒率（合计） | 4.52% | 4.39% |
| 训练完成度 | 40% | 100% |

**从训练日志看，`model_2000` 很可能是更好的交付选择**：任务能力几乎持平（误差甚至更低），
风格分高出 32%。但——

⚠️ **风格分 ≠ 观感。** 这个判断目前只基于奖励指标，还没有 gait 指标（支撑占比等）和视频佐证。
必须跑完下一节的对比才能定论。

## 6. 手段：可以怎么解决风格回退

按"代价从小到大"排：

| 手段 | 做法 | 代价 |
|---|---|---|
| **提前停止**（本次采用） | 用风格峰值附近的 checkpoint | 0，今晚即可验证 |
| 调**小** λ（`task_style_lerp`） | 0.5 → 0.3，**减小**任务权重＝加大风格话语权 | 一次重训 ≈ 2.7 h |
| | ⚠️ 2026-10-20 更正：λ 是**任务**权重不是风格权重（源码 `amp.py:203`），初稿写成"调大 λ"是反的 | |
| 削弱判别器更新 | 降低判别器 learning rate 或更新频率 | 一次重训 |
| 更强的正则 | 加大 `grad_penalty`，或加谱归一化 | 需改底层代码 |
