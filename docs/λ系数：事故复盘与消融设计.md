## 1. λ 的精确语义（源码级）

`rsl_rl/rsl_rl/modules/amp.py:203`：

```python
return self.task_style_lerp * task_reward + (1.0 - self.task_style_lerp) * style_reward
```

| λ | 合成奖励 | 行为 |
|---|---|---|
| 0.0 | 纯 style | 没有任何任务奖励 → 原地摆姿势最优（10-20_18-02-56 已实测） |
| 0.5 | task + style 各半 | 标准 AMP |
| **1.0** | **纯 task** | **= 普通 PPO，风格奖励系数 0，判别器完全不影响策略** |

**易错点**：直觉容易把 "lerp=1.0" 理解成"更偏向 AMP"。方向是反的。
`08_train_resume.sh` 里的注释（"0.3 保守 / 0.5 默认 / 0.7 重风格"）就是这么写反的，
`11_run_all_evals.sh` 的注释是对的。前者待修正。

## 3. 为什么从日志看不出来（最关键的教训）

AMP 的 `Episode_Reward/style` 是**独立记录**的，记录的是判别器的原始输出，
**不经过 lerp 加权**。所以即使 λ=1.0 让风格奖励对策略的影响为 0，
日志里照样稳定打印 0.7 左右的风格分。

> **教训：日志里"在记录的量" ≠ "在起作用的量"。**
> 验证一个超参数有没有生效，不能看它被记录的那一栏，
> 要去 `run 目录/params/*.yaml` 里读这次 run 实际用的值。

## 6. 风格分随迭代的实测（用户的问题 2）

数据源：旧 run（λ=0.5）的 tfevents，每点取前 200 iter 窗口均值。
工具：`scripts/dump_tb.py`。

| iter | 风格分 | 线速度跟踪 | 转向跟踪 | 动作率惩罚(越近0越平滑) | 摔倒率 |
|---|---|---|---|---|---|
| 500 | 0.494 | 0.102 | 0.127 | −0.141 | 0.098 |
| 1000 | 0.737 | 0.575 | 0.293 | −0.106 | 0.063 |
| 1500 | 0.734 | 0.658 | 0.329 | −0.076 | 0.041 |
| **2000** | **0.775** | 0.670 | 0.392 | −0.052 | 0.035 |
| 2500 | 0.745 | 0.656 | 0.411 | −0.046 | 0.043 |
| 3000 | 0.711 | 0.652 | 0.422 | −0.043 | 0.040 |
| 3500 | 0.697 | 0.650 | 0.443 | −0.039 | 0.032 |
| 4000 | 0.651 | 0.650 | 0.439 | −0.039 | 0.037 |
| 4500 | 0.633 | 0.651 | 0.439 | −0.037 | 0.033 |
| 5000 | 0.606 | 0.657 | 0.431 | −0.038 | 0.035 |

### 结论

1. **用户的直觉对**：amp_2000 的风格分确实最高（0.775 vs 0.651，+19%）。
2. **但风格分单独看是误导指标**。2000 之后训练在另外三个轴上继续变好：
   - 动作平滑 +25%（−0.052 → −0.039）
   - 转向跟踪 +12%（0.392 → 0.443）
   - 而线速度跟踪在 1500 iter 就饱和了（0.658 → 0.657，没再涨）
3. **风格分下降的机制**：策略被逼着去跟 2.5/3.0 m/s 这些
   **LAFAN1 人类数据里根本不存在的速度**，动作必然偏离人类分布 → 判别器扣分。
   这是 AMP 的固有张力，不是训崩了。

## 7. λ 消融实验设计

### 7.1 为什么值得做

λ 是**唯一一个能在这条帕累托前沿上连续滑动的旋钮**：
λ↑ → 跟踪更好、风格更差；λ↓ → 风格更好、跟踪更差。
第 6 节的数据已经证明这个前沿客观存在（同一条训练轨迹上就走过了 0.775→0.606）。
所以 λ 不是一个"随便调调"的数，它是可以直接进简历的一张图。

### 7.2 设计

| 项 | 取值 |
|---|---|
| λ 扫描点 | **0.25 / 0.5 / 0.75**（0.0 与 1.0 端点已有现成 run，不必重跑） |
| 固定 | seed 42、4096 envs、同一奖励表（含对称奖励）、同一参考动作 |
| 训练长度 | **1500 iter** |
| 指标 | ①6 档速度跟踪误差 ②最高可达速度 ③风格分（稳态窗口均值） ④SI_clear ⑤25s 横漂 |
| 决策规则 | 先用 ①② 淘汰跟踪不合格的，再在合格者里取风格分最高的 |

**为什么 1500 iter 就够**：第 6 节显示线速度跟踪在 1500 iter 已达 0.658/饱和值 0.657。
短周期足以把不同 λ 分开，成本只有长跑的 1/3。
**同 iter 对比是硬要求** —— 拿 1500 的 A 去比 4000 的 B 是无效的。

### 7.3 成本

| 方案 | 内容 | 时长 |
|---|---|---|
| A 只保主模型 | λ=0.5 训到 4000 iter | 3.3 h |
| B 只保消融 | 3×1500 iter 扫描 | 3.8 h |
| C 先扫后精（推荐） | 3×1500 扫描 → 选最优 λ → 该 λ 续训到 4000 | 5.9 h |

单卡 3090，实测 3.0 s/iter。
