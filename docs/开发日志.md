### 10:52-10:56 第一次安装失败（两个连环坑）

**现象**：日志报 `ERROR: No matching distribution found for isaacsim[all,extscache]==5.1.0`，
pip 列出的可用版本只有 4.0.0.0 ~ 4.5.0.0，没有 5.x。

**排查顺序**：
1. 看日志发现前面有 `conda activate` 失败：`EnvironmentLocationNotFound: Not a conda environment`
2. 再看 `python: 未找到命令` —— 说明 env 根本没激活成功，后续命令全跑在系统环境上
3. 系统 Python 是 3.10，而 isaacsim 5.x 的 wheel 只有 cp311

**真凶**：
- 坑 1：conda 25.9 必须先接受 Anaconda 频道服务条款，否则 `conda create` 静默失败
  （报错只给了一个 anaconda.com 文档链接，很容易看漏）
- 坑 2：因此 `activate` 失败，`pip` 用的是系统 3.10 的 pip，看不到 cp311 的 5.x wheel
- 连锁反应：torch 被误装进系统 Python，占掉系统盘空间

**可复用规律**：
1. 新版 conda 在非交互脚本里要先 `conda tos accept --override-channels --channel <url>`
2. 安装脚本里**永远用 env 的绝对路径 python/pip**，不要依赖 `conda activate`（失败是静默的）
3. 安装前先 `df -h`，大件必须落到数据盘

### 11:05 踩坑：pkill/pgrep 会匹配到自己

**现象**：远程执行 `pkill -f 01_install_env.sh; ...` 返回空输出、无退出码。

**真凶**：`pkill -f` / `pgrep -f` 匹配的是完整命令行，而**执行这条命令的 bash 进程自身的命令行里就含这串字符串** → 自杀。
之前那个"进程还活着(ALIVE)"的报告也是 pgrep 匹配到自身的误报，安装进程其实早就退出了。

**规律**：远程查进程要用 `ps -eo cmd | grep -c '[i]nstall_env'`（字符类避免自匹配），
不要用 `pkill -f <脚本名>` 这种会自匹配的写法。
