## 1. 评估方法（先说清楚数字是怎么来的，否则数字没有说服力）

| 要素 | 做法 | 为什么 |
|---|---|---|
| 速度档 | 6 档：0.5 / 1.0 / 1.5 / 2.0 / 2.5 / 3.0 m/s | 覆盖人类从慢走到跑的完整区间 |
| 指令 | 每个 env 一个固定档，**每一步都覆写** | CommandManager 会按 `resampling_time_range` 重新采样，不覆写会漂回随机范围 |
| 采样长度 | 1500 步 × 0.02 s = 30 s | 够数 20+ 个步态周期 |
| 启动剔除 | 前 5 s 不计入统计 | 从参考姿态站起来、速度还没起来，计进去会把低速档拉偏 |
| 稳态误差 | 额外报一列"去掉前 10 s"的误差 | 见 §5，2.5 m/s 档存在启动暂态 |
| 扰动 | `push_robot` 推力置零 | 要的是干净步态，不是鲁棒性测试 |
| 对照 | 三个模型共用同一套脚本、同一 seed=42 | 唯一变量是 checkpoint |

**人类参照值**（`HUMAN_DUTY`）是 gait 实验室的典型量级（步行≈0.60、跑≈0.30），
**不是精确引用值**，只当"数量级是否合理"的参照带。真正硬的结论来自我们自己测的
秩相关、速度误差、CoT —— 那三个不依赖任何外部文献。

## 3. 发现一：AMP 确实学到了"一族"步态，不是"一个步态拉伸"

支撑占比从 0.78 单调降到 0.35，与人类参考带（0.68 → 0.31）同构。
这不是"走模式/跑模式"的台阶式硬切，而是**随速度连续变形**——这正是
"拟人态走跑"最硬的证据。秩相关 −0.83/−0.94 说明单调性很强（唯一破坏单调的是
2.5 m/s 档，见 §5）。

---

## 4. 发现二（最有价值）：风格奖励单独用会被 exploit

`style_only`（λ=0，完全没有任务奖励）的结果：

| 指标 | style_only | AMP |
|---|---|---|
| 判别器给的风格分 | **0.979（最高）** | 0.60 – 0.80 |
| 支撑占比 | **0.82 – 0.93**（几乎不抬脚） | 0.35 – 0.79 |
| 步频 | **0.23 – 0.45 Hz**（极慢） | 0.93 – 1.53 Hz |
| 实际前进速度（由步长×步频反推） | **≈ 0.1 – 0.2 m/s** | 与指令一致 |
| 速度跟踪误差 | **1.41 m/s** | 0.22 – 0.27 m/s |
| CoT | **1.20**（AMP 的 2 倍） | 0.60 – 0.62 |

**风格分最高，步态最差。** 这不是矛盾，是机制使然：

判别器的输入是 **4 帧 × 61 维 = 角速度(3) + 关节角(29) + 关节速度(29)**，
**刻意不含世界坐标的绝对位置、也不含根节点的线速度** —— 这是有道理的设计，
否则策略会去学"在场地某个角落走路"，而不是学"走路的风格"。

但代价是：**判别器根本看不见机器人有没有真的在往前走。**
于是策略找到了一个漏洞 —— 原地做一套关节角度很像人的慢动作
（支撑占比 0.92 = 脚几乎不离开地面，像在原地蹭），
判别器给 0.98 分，但机器人 30 秒只挪了 0.1–0.2 m/s。

> 大白话：判别器是个只看关节姿势、不看位移的裁判。你原地摆出跑步的姿势，
> 它照样给你满分。所以**风格奖励不能单独用**——它必须和任务奖励绑在一起，
> 让"真的跑起来"这件事成为硬约束。这就是 λ 为什么要取 0.5 而不是 0。

这条是本项目最值得讲的一个发现：**它不是一个"调参调出来的结果"，
而是一个可以被机制解释的、有因果的失败模式。**

## 5. 发现三：风格分下跌 ≠ 步态变差（对昨天结论的再修正）

昨天从训练曲线发现"风格分从 0.797（iter 2000）跌到 0.602（iter 4999）"，
据此推测"最终交付该用 model_2000"。**步态指标不支持这个推测**：

| | amp_2000 | amp_4999 | 谁更好 |
|---|---|---|---|
| 支撑占比秩相关 | −0.83 | **−0.94** | 4999 |
| 与人类参照带偏差 | 0.077 | **0.069** | 4999 |
| 平均 CoT | 0.62 | **0.60** | 4999 |
| 平均速度误差 | **0.224** | 0.267 | 2000 |
| 稳态速度误差 | **0.156** | 0.201 | 2000 |

后 3000 轮训练：
- **变好的**：步态形状更贴人类（秩相关 −0.83 → −0.94，偏差 0.077 → 0.069）、能耗略降
- **变差的**：速度跟踪（0.156 → 0.201），且在 1.5 / 2.0 / 3.0 三档高速上退化最明显
  （0.108 → 0.233、0.154 → 0.200、0.136 → 0.206）

**为什么风格分跌了，步态指标却没跌？** 两个可能，目前数据不足以区分：
1. **判别器的尺子在变严**：判别器全程持续变强（策略分 −0.548→−0.677、
   参考分 +0.551→+0.678），同一套动作在更强的判别器下得分自然会降。
   但两者差距也在拉大（1.099 → 1.355），所以不能全部归因于此。
2. **策略牺牲的是判别器看得见的细节**（关节微协调、手臂摆动），
   而 duty factor / CoT 这类"大尺度"指标反而被任务侧继续优化了。

→ 已排 checkpoint 阶梯评估（iter 1000/3000/4000）来区分这两种解释，见 §7。

## 6. 已知弱点（诚实写，被问到不慌）

**2.5 m/s 档的启动暂态。** 三个不同 checkpoint 上，2.5 m/s 都是误差最大的一档。
分段均速显示（`analyze_gait.py` 的诊断输出）：

```
env4 cmd=2.5  分段均速 = ['0.14', '2.38', '2.08', '2.43']
```

前 6 秒几乎没动，之后稳定在 2.1–2.4 m/s。**是启动慢，不是稳态跟不上。**
去掉前 10 s 后误差从 0.806 降到 0.381（amp_4999）。
2.0 和 3.0 档都没有这个现象，怀疑是走→跑过渡带上策略存在犹豫区。
这条要在报告里主动讲 —— 主动承认比被问出来可信得多。

## 8. 模型选型（暂定，待阶梯数据确认）

当前证据下 `amp_4999` 略占优：三个"拟人"指标（单调性、参照带偏差、CoT）全胜，
只在速度跟踪上输给 `amp_2000`。

但这不是压倒性的。**倾向于以 `amp_4999` 作为主交付模型**——理由是可解释：
它是训练收敛的产物，拟人指标最好；而 `amp_2000` 作为"提前停止"的对照写进报告，
正好构成"我检查过训练是否过犹不及"的证据。

若阶梯数据显示指标在 iter 3000 之后进入平台期，则 4999 的选择没有争议；
若显示 3000 之后持续退化，则改用 3000/4000 档。
