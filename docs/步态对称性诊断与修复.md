# 步态对称性诊断：「瘸」是怎么被量化、归因、修复的

> 开始：2026-10-22 15:20 ｜ 状态：诊断完成，修复进行中
> 触发：面试官反馈「走路有点瘸」，用户追问「是不是任务奖励也需要调」
> 数据来源：`backup/eval_out/gait_amp_model_4000.npz`（20s × 6 速度档）

---

## 0. 一句话结论

**「瘸」是真的，不是观感问题，也不是录制问题。**
`G1AmpRewards` 的 15 个奖励项里没有任何一项约束左右腿对称性，
优化器因此没有任何动力去修它。框架自带的 mirror loss 在数学上抓不到这个量
（它约束单帧镜像，而跛行是周期级现象）。

---

## 1. 怎么把「瘸」变成可证伪的量

三个互相独立的指标，全部只用双边足端高度 `foot_z`（`(T, 6, 2)`，6 个速度档 × 2 只脚）：

| 指标 | 定义 | 人类正常值 | 来源 |
|---|---|---|---|
| **抬升对称指数** `SI_clear` | `2·|L−R|/(L+R)`，L/R 为逐步抬升高度的中位数 | < 5% | 步态分析通用定义 |
| **支撑对称指数** `SI_stance` | 同上，用逐步支撑时长 | < 5% | 同上 |
| **周期变异系数** `CV` | 步周期的 std/mean，左右分别算 | ~0.05–0.10 | 人类步态节律性研究 |

关键设计：**用逐步中位数而不是极值**。
第一版用 `z.max()-z.min()` 算抬升，得到 0.5 档 72.7%、2.0 档 70.7% 的夸张数值——
但那是被单步异常（一次异常高抬腿）污染的结果。
改成「逐步切分 → 每步独立算 → 取中位数」后，数值降到 7.7%–27.7%，才是可信的。

> **可复用的规律：用极值算对称性，等于让一步异常定义整个步态。**
> 必须逐步分解后取中位数/分位数。

## 2. 实测结果

```
档位        0.5     1.0     1.5     2.0     2.5     3.0
抬升SI     16.1%    7.7%   27.7%   13.1%   11.1%   21.0%
支撑SI     16.7%    3.1%   11.8%    0.0%    0.0%    0.0%
左腿CV     0.209   0.209   0.249   0.263   0.197   0.068
右腿CV               0.221   0.087   0.064   0.087   0.061   0.132
```

三条独立证据：

1. **抬升 SI 全部 > 5%**，最严重 27.7%（1.5 m/s）
2. **6 档里有 5 档是「左脚抬升 < 右脚」**，方向高度一致 → 系统性偏置，不是随机噪声
3. **左腿周期 CV 在 1.0/1.5 档是右腿的 2.4×/3.9×** → 左腿节奏更乱，是「坏腿」

**左腿是坏腿**这个结论，与「左脚抬得低（更容易拖地）+ 周期不稳」两条互相印证。

## 3. 归因：为什么优化器没有去修它

### 3.1 奖励里根本没有这一项

`G1AmpRewards` 全部 15 项：

| 类别 | 项 |
|---|---|
| 任务 | `track_lin_vel_xy_exp`, `track_ang_vel_z_exp` |
| 姿态正则 | `flat_orientation_l2`, `lin_vel_z_l2`, `ang_vel_xy_l2` |
| 平滑/能耗 | `dof_torques_l2`, `dof_acc_l2`, `action_rate_l2` |
| 限位 | `dof_pos_limits` |
| 归位 | `joint_deviation_hip/arms/waist` |
| 足端 | `feet_air_time`, `feet_slide` |
| 终止 | `termination_penalty` |

**没有一项**涉及左右对称。`feet_air_time_positive_biped` 只看「是否单脚支撑 + 腾空够长」，
两只脚各自独立判断，**不管它们是否一样**。

### 3.2 mirror loss 为什么救不回来（关键）

`rsl_rl_ppo_cfg.py` 里确实开了：

```python
symmetry_cfg = RslRlSymmetryCfg(
    use_data_augmentation=True,
    data_augmentation_func=g1.compute_symmetric_states,
    use_mirror_loss=True,
    mirror_loss_coeff=0.1,
)
```

`g1.compute_symmetric_states` 做的是：交换左右关节索引 + 翻转 roll/yaw 符号。

它约束的是：

```
π(mirror(s(t)))  =  mirror(π(s(t)))
```

**同一时刻、单帧状态**的镜像等变性（equivariance）。

而跛行的定义是：

```
左脚在 [t, t+T] 内累计位移 0.14 m
右脚在 [t, t+T] 内累计位移 0.19 m
```

这是一个**跨半个周期的时序统计量**。

> mirror loss 从来没有「看过」一个完整的步态周期，
> 所以它在数学上无法对这个量产生任何梯度。

**这与判别器的盲区是同一个病**：
- 判别器输入 4 帧（0.08 s）→ 看不到 25 秒的横向漂移 → 被 λ=0 的「原地摆姿势」exploit
- mirror loss 输入 1 帧 → 看不到一个周期的左右不对称 → 跛行不受惩罚

**共性规律：局部约束抓不住全局性质时，策略一定会去 exploit 这个盲区。**

## 4. 顺带查出的第二个问题：PLAY 配置漏了三行

对比 legged_lab 自带的 `G1FlatEnvCfg_PLAY`（velocity 任务）：

```python
self.observations.policy.enable_corruption = False   # 关观测噪声
self.events.base_external_force_torque = None        # 关外力
self.events.push_robot = None                        # 关随机推
```

而 `G1AmpEnvCfg_PLAY` 只有：

```python
self.events.reset_from_ref = None
```

**三条全缺。** 后果：

| 缺的项 | 实际影响 |
|---|---|
| `push_robot = None` | 每 5 秒把速度**直接改成** `x,y ∈ (-0.5, 0.5)` 的随机值 |
| `enable_corruption = False` | `joint_vel ±1.5 rad/s`、`base_ang_vel ±0.2 rad/s` 噪声仍在 |
| `heading_command` 未关 | 机器人一直在跟随机航向转弯；PLAY 里 heading 改成 (0,0) 但初始朝向不为 0 时会先转向 |

**`push_robot` 的 `velocity_range = {"y": (-0.5, 0.5)}` 是横向漂移的直接来源。**
之前把侧漂归因于「λ 稀释了横向惩罚」，属于过度归因——真正的元凶是每 5 秒一次的
±0.5 m/s 横向速度冲击。

> **可复用的规律：所有展示视频和评估，都必须先确认「环境里还有什么在动」。**
> 训练配置带域随机化是对的，但 play / eval 必须显式关掉，
> 且要**逐行对比同类任务的 PLAY 配置**——框架不会提醒你漏了哪一行。

## 5. 修复方案

| # | 问题 | 修法 | 需要重训 |
|---|---|---|---|
| 1 | 侧漂 / 画面晃 | PLAY 补 `push_robot=None`、`enable_corruption=False`、`heading_command=False` | ❌ 不用 |
| 2 | 左右不对称 | 加 `air_time_variance_penalty`（权重 −2.0） | ✅ 要 |
| 3 | 左脚抬升低 / 拖地 | 加 `feet_clearance`（权重 1.0，target 0.1，照抄 G1 官方） | ✅ 要 |

### 权重依据（不拍脑袋）

| 项 | 框架内已有用法 | 本项目取值 | 理由 |
|---|---|---|---|
| `feet_clearance` | G1 flat: weight 1.0, target 0.1, std 0.05, tanh_mult 2.0 | **完全相同** | 同一机器人、同一地形 |
| `air_time_variance_penalty` | GO2 flat: weight −1.0 | **−2.0** | 双足只有两只脚，方差量级更小；且 λ=0.5 把任务奖励稀释一半，需补回 |

### 为什么用 `air_time_variance_penalty` 而不是 `feet_gait`

`feet_gait` 强制固定周期与相位（`period` 是常数），会**锁死步频**，
与「响应 0.5–3.0 m/s 任意速度、步频需要随速度变化」的需求直接冲突。

`air_time_variance_penalty` 只惩罚左右**差异**，不规定绝对值 ——
步频可以随速度自由变化，只要左右一致。这才是对的约束。

## 6. 诚实边界

1. **修复效果尚未验证。** 以上是诊断与方案，不是结果。
2. **SI < 5% 是文献量级参照，非精确引用。** 硬结论是「本项目左右腿差异 7.7%–27.7%」，
   以及「5/6 档方向一致」。
3. **n=6（6 个速度档）不是独立样本**，不能拿来做严格统计推断。
4. **仍是纯仿真，未上真机。**
5. **`feet_clearance` 的 target_height=0.1 是官方值**，但本项目实测支撑期脚底 z=0.035，
   实际目标抬升 0.065 m。如果要抬更高需要另调，参数沿用官方是为了减少未验证变量。
