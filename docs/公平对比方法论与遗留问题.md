# 公平对比方法论 + 遗留问题清单

> 建立：2026-10-21 23:20
> 起因：用户质疑"拿任意速度走跑要求 DeepMimic 是流氓逻辑" —— 这个质疑成立，
> 它暴露了本项目对比实验里的**评测协议偏置（evaluation protocol bias）**。

---

## 0. 一句话结论

**DeepMimic 不是"被 AMP 打败的对手"，而是"被排除的候选方案"。**
它的实测表现（duty 秩相关 −1.00、关节误差 6.10°）**优于** AMP（−0.94）。
拿自己有而对方没有的能力当尺子，是协议偏置，不是性能优势。

---

## 1. 问题：现有对比为什么不公平

`docs/AMP_vs_DeepMimic对照实验.md` 里的对比，隐含使用了 AMP 的能力作为评判标准。

| 能力 | DeepMimic | AMP | 机制原因 |
|---|---|---|---|
| 产生自然动作 | ✅ | ✅ | 都有风格来源 |
| 逐帧复现指定动作 | ✅ | ❌ | 时间轴推进 vs 无时间轴 |
| 响应外部速度指令 | ❌ | ✅ | 观测组无 command 项 |

后两列**只有一方具备**，是"能力的有无"，不是"分数的高低"。

### 核心原则

> **第 1 列（动作自然度）才是唯一能打分的区域。**
> 第 2、3 列只能用来**排除方案**，不能用来**排名**。

---

## 2. 正确的对比设计：四步

### 第 1 步：clip 速度直方图（前置，纯离线）

对 30 段 LAFAN1 clip 逐帧计算 root 水平速度，得到速度分布。

**必须先做这一步**：已实测这 30 段 clip 的 x 分量均值为 **−0.249**（混有转弯与倒退片段），
说明 clip 的实际速度分布与"0.5–3.0 均匀"相去甚远。
若某档（如 2.5 / 3.0 m/s）没有对应 clip，该档应直接声明**不可比**，不硬凑。

### 第 2 步：速度匹配（speed-matched）评估

| 模型 | 达到目标速度 v 的方式 |
|---|---|
| DeepMimic | 挑 clip 中速度最接近 v 的片段复现 → **它机制内的最优表现** |
| AMP | 下发指令 v |

**不做这步，duty / 步频 / 步长全部不可信。**
因为这三个量本身就是速度的函数；速度分布不同会造成系统性偏移，
测到的差异是"跑得不一样快"，而不是"谁更像人"。

### 第 3 步：指标体检

| 指标 | 能用作优劣证据吗 | 原因 |
|---|---|---|
| duty / 步频 / 步长 | ✅ 速度匹配后可 | 纯物理量 |
| CoT | ✅ | 纯物理量 |
| 稳态速度误差 | ⚠️ **须改定义** | 目标速度改为"该 clip 的人类速度"，非外部指令 |
| **判别器风格分** | ❌ **完全不可用** | 判别器在 AMP 自生成数据上训练，给 AMP 打分是开卷考试 |
| 逐帧关节跟踪误差 | ❌ | AMP 无参考帧，指标无定义 |

#### 判别器自评有偏（本项目最需要主动交代的一条）

文档里"λ=0 拿到 0.979 风格分"的分数来自 **AMP 自己的判别器**。
用同一把尺子量 DeepMimic = 用 AMP 的审美标准评价 DeepMimic。

#### 替代：无裁判的自然度指标

| 指标 | 做法 | 为什么公平 |
|---|---|---|
| 关节角分布距离 | rollout 关节角分布 vs LAFAN1 人类数据，算 **MMD / 逐维 KS / Wasserstein** | 对称、无参考帧、不依赖任何训练出来的裁判 |
| 躯干垂直振荡 + 头部加速度 RMS | 人类行走垂直起伏仅几 cm，头部平稳 | 物理量 |
| 步态周期性 | 自相关峰锐度 / 谱熵 | 人类步态高度周期性，双方都能算 |

> ⚠️ **当前状态：以上三项一项未做。** 且第 2、3 项需要 base height 与姿态角，
> 而现有 npz **未存这两个量**（见 `技术报告_一页版.md` 诚实边界 §5），需重跑 eval。

### 第 4 步：把不可比项转为"需求匹配"陈述

需求匹配论证三句：

1. **需求定义**：机器人须在 0.5–3.0 m/s 连续范围内响应指令走跑
2. **DeepMimic 结构上不满足**：观测组无速度指令项
   （`deepmimic_env_cfg.py:87-108` 逐行核验），源码级确定，**与调参无关**
3. **故它是排除项，不是输家**

**该论证不依赖 DeepMimic 表现差。**

## 3. 这个对比有必要吗

| 目的 | 有没有必要 | 理由 |
|---|---|---|
| 发论文证明 "AMP > DeepMimic" | ❌ 没必要，也不成立 | 不公平；且 AMP 非本人提出，赢了也不是自身贡献 |
| 证明 "我选 AMP 是对的" | ✅ 有必要 | 但论证形式须从**性能对比**改为**需求匹配** |

### 面试里最可能的反问与答法

> **"可 DeepMimic 的 ρ = −1.00，比你的 −0.94 好啊，你怎么证明 AMP 更好？"**

**不要辩护性能。** 应当答：

> "我不主张 AMP 在自然度上比 DeepMimic 强 —— 数据上它 ρ 更单调，我不争这一条。
> 我把 DeepMimic 排除的依据不是它差，是它不满足我这个任务的需求定义：
> 我要的是能在 0.5–3.0 m/s 连续响应指令的控制器，
> 而 DeepMimic 的观测组里没有速度指令项，这是源码级确定的结构差异，不随调参改变。
> 它做得很好，只是做的不是我需要的那件事。"

**方法论要点：对手越强，越不能当手下败将。**

## 4. "丑"如何翻译成可证伪量（方法论沉淀）

翻译链条：**主诉现象 → 行为特征 → 标量 → 外部预测**（第四步才使其成为可证伪）。

| 主诉"丑"的表现 | 标量 | 算法 | 外部参照 / 证伪条件 |
|---|---|---|---|
| 高频小碎步 | 步频 `stride_freq` | 触地计数 / 时长 | 人类 1.8–2.2 Hz，>2 倍 → 碎 |
| 倒腾快但不前进 | 步长 `stride_len` | `v / freq` | 1.4 m/s 时人类 0.7–0.8 m，短一半 → 碎 |
| 脚不离地 | 支撑占比 `duty` | 支撑帧占比 | 人类走 0.6 / 跑 0.3，>0.8 → 拖地 |
| 脚乱蹭 | 足端抬升 `foot_clear` | 摆动最高 − 支撑最低 | 过小 → 蹭地 |
| 只有一个步态在拉伸 | duty vs v 秩相关 ρ | Spearman | ρ 应 ≈ −1，ρ>0 即未学到速度与步态的关系 |
| 僵硬费劲 | 运输能耗 `CoT` | 机械功 /(mg·距离) | 人类 ≈ 0.2，高 4 倍 → 费劲 |

### 三条设计原则

**原则 1｜指标不能依赖参考动作。**
AMP 不逐帧跟踪参考动作，"关节跟踪误差"对它无定义。
所有指标只用物理量与人类统计量，保证双方都能算。

**原则 2｜每个指标都要配"防作弊搭档"。**
单指标可 hack：λ=0 那组判别器给 0.979 分，看着完美，
但 duty=0.9 + 步频 0.23 Hz + 实际速度 0.1 m/s —— 三指标交叉即锁死"原地摆姿势"。

**原则 3｜区分硬结论与参照带。**
ρ、速度误差、CoT 是**自测所得，不依赖文献** → 硬结论。
人类 0.6 / 0.3 等是文献量级，只判"数量级是否合理"，已明确标注"非精确引用"。
**无此区分，"丑"仍是品味问题。**

## 6. 若指 ACT（LeRobot 的 Action Chunking Transformer）

与 DeepMimic 是另一种错配：

| | ACT | DeepMimic |
|---|---|---|
| 数据来源 | 遥操作示范数据 | 动作捕捉数据 |
| 目标 | 完成任务 | 复现动作 |
| 指令接口 | 无（输出动作块） | 无（时间轴推进） |

比之前须先固定"数据来源"变量，否则又是一次协议偏置。
且两者都无速度指令接口，同样要先划能力边界再谈打分。
